Usage: forge implement <track>/<feature>

Start the feature's phases, up to $FORGE_CONCURRENCY (default 10) sessions
at once. The feature must be ready (every dependency shipped) and
allocated (forge alloc), with none of its sessions live (listed by claude
agents with state working or blocked). Also restarts a feature whose
phases were replanned after a reopened discuss.

A phase's repo is the split's "repo": a git repo directly under the
project root, else the .forge/repos.json entry with that directory name
(a linked repo, its path relative to the project root). A phase without
"repo" runs in the project root. Planning state stays in the project root.

On a fresh run (no phase has events.jsonl or result.json), fails when a
phase's repo already has a forge/<track>-<feature> branch, naming the repo and
the branch, and creates no worktree. forge resume skips this check.

Branches and worktrees carry the track, so features of the same name in
two tracks never share one.

In each phase's repo:
  - a worktree on forge/<track>-<feature> at .claude/worktrees/<track>-<feature>
  - a worktree on forge/<track>-<feature>-<N> at .claude/worktrees/<track>-<feature>-<N>,
    branched from forge/<track>-<feature>; each start first merges forge/<track>-<feature>
    into the phase branch
Before each worktree, forge exclude makes sure .claude/worktrees/ is
git-ignored in that repo.
Then starts, in number order, each phase with no result whose
dependencies are done (result done and branch merged into forge/<track>-<feature>)
and that is not running, until the feature's running phases reach
$FORGE_CONCURRENCY (default 10). A phase is running while it has no result
and its latest start event is newer than its latest wait, retry or replan
event and claude agents --json --all lists the session that start event
names in a state other than crashed or stopped (an idle "done" session
still counts). A running phase whose session is blocked (waiting on an
operator question) is not started again but holds no place under
$FORGE_CONCURRENCY. A running phase whose session is gone is started again,
printing "forge: phase <N>'s session <name> is gone; relaunching it" on
stderr. A phase that already has a live session under any of its names
("<project> P<N> <track>/<feature>" or "<project> P<N>R<k>
<track>/<feature>", or the legacy "<project> <track>-<feature> Phase
<N>[ retry <k>]") is never started again: it keeps its slot and the skip
is reported as a refused start (below), naming the session.

Starts are also capped machine-wide. Under
${XDG_RUNTIME_DIR:-~/.local/state}/forge/sessions.lock, held from the
count through the last start, forge counts the live forge sessions of
every project once: claude agents --json entries with any forge session
name: "<project> P<N>[R<k>] <track>/<feature>",
"<project> verify|ship|discuss <track>/<feature>", "<project>
quick|fast|new <task>", "<project> debug <symptom>", or the legacy
"<project> <track>-<feature> Phase <N>[ retry <k>]", "... Verify" or
"... Ship", whose state is not blocked, done, failed, stopped or
crashed, so a session waiting on a question holds no place. Each session
the call starts adds one. At or above $FORGE_MAX_SESSIONS (default 12,
set per host in ~/.config/forge/env) it starts nothing more, prints
"forge: <n> forge sessions live; phase <N> waits for a free session" on
stderr (n the machine-wide count) and exits 0; the phase stays due and
the next forge implement, done, next or resume that finds room starts it.

Starts also wait for memory, checked under the same lock before each
start, after the count: MemAvailable from /proc/meminfo must be at
least 3 GiB plus 1 GiB for this start and 1 GiB for each phase the call
has already started; otherwise it prints "forge: MemAvailable <x> GiB;
phase <N> waits for memory" (x to one decimal) on stderr and exits 0,
the phase left due. An unreadable MemAvailable is an error (exit 1).
Verify and Ship starts go through the same checks, naming
"<track>/<feature> Verify" or "<track>/<feature> Ship" in place of
"phase <N>".

Each held start is recorded in
${XDG_STATE_HOME:-~/.local/state}/forge/held.jsonl, one line
{"root": <project root>, "kind": "phase"|"verify"|"ship", "target":
"<N>"|"<track>/<feature>", "time": <UTC time>}: a held phase together
with every later due phase not yet started, or the held Verify. A record
of the same root, kind and target is kept as it is, so the first hold
time stays; $FORGE_HELD_SINCE, when set, is the time of a new record.
Each record prints "forge: recorded the held <kind> <target>; forge
watchdog starts it once room frees" on stderr, and forge watchdog starts
it once room frees (a phase through forge resume <N>, a Verify through
forge implement <track>/<feature>, a Ship through forge next
<track>/<feature>). When the record cannot be written it prints "forge:
warning: cannot record the held <kind> <target> in <file>" on stderr and
the exit stays the same.

Under the same lock, before it counts, each forge implement, done,
resume and next that starts phases claude rm's this project's finished
sessions once:
  - the finished sessions of archived features (the session targets of
    forge gc --help)
  - each background (claude --bg) session whose state is done, whose
    name starts with "<project> " and whose cwd is at or under the
    project root or a linked repo of .forge/repos.json, when it is
      a phase session ("<project> P<N>[R<k>] <track>/<feature>" or the
      legacy "<project> <track>-<feature> Phase <N>[ retry <k>]") whose
      STATE/phases/<N>-*/result.json has status done, or
      a "<project> quick <task>", "<project> debug <symptom>" or
      "<project> discuss <track>/<feature>" session whose transcript
      (~/.claude/projects/<cwd, each non-alphanumeric as ->/<sessionId>.jsonl)
      ends in assistant text holding a line starting "result:" outside a
      ``` fence, and whose cwd's git status lists no modified tracked
      path outside .forge/
Every other session stays: an interactive one, another project's, one
in any state but done, a phase whose result is blocked, failed or
missing, and a quick, debug or discuss session without that result line
or with uncommitted work. A missing or unreadable transcript or a failed
git status prints a warning on stderr and keeps the session. Each
removal prints "forge: removed <name> (<id>)" on stderr and appends
"<UTC time><TAB><id><TAB><name>" (time as date -u +%Y-%m-%dT%H:%M:%SZ,
id the short claude agents id) to <git common dir>/forge-reaped.log of
the project root. A failed claude rm prints "forge: warning: cannot
remove session <id>", logs nothing and does not fail the call. claude rm
keeps the transcript and the session's worktree.

Each start first claude rm's every session of the same name, runs
  claude --bg -n "<project> P<N> <track>/<feature>" --model opus
    --effort medium --permission-mode $FORGE_PERMISSION_MODE
    --settings '{"env":{"FORGE_PORT_OFFSET":"<o>","FORGE_TEST_DB":"<db>","FORGE_ROOT":"<root>","FORGE_PHASE":"<N>"}}'
    "/forge-phase <root> <N>"
and logs a start event carrying the offset <o>. When a worktree cannot
be created, it logs no start event for that phase and exits 1 (so do
forge done, next and resume, which start phases the same way). A failed
claude --bg is a refused start (below). <o> is the lowest multiple of
10, from 10, that no live forge phase or verify session of any project
holds: each session claude agents --json --all lists in a state other
than crashed or stopped holds the offset of its last start event (a
phase's in STATE/phases/<N>-*/events.jsonl, a verify's in
STATE/features/<track>-<feature>/events.jsonl, STATE being the state
dir of the project whose directory name its name starts with, found as
the nearest ancestor of the session's cwd with that name or holding a
directory of that name with a .forge, as for a linked repository's
session; a renamed session in a <repo>/.claude/worktrees/ worktree holds
the offset of the start event carrying its id in the state dir of the
nearest ancestor of <repo>, or a directory in it, whose state dir root
file names it, the project root's and each child repo's alike; no state
dir is created by the scan), or (N mod 100) *
10 for a phase with no offset logged; offsets given earlier in the same
call are taken too.
<db> is <project>_test_<N>, with each non-alphanumeric character of the
project directory name as _. A verify session gets its own <o> the same
way; ship sessions get neither.

Before each phase start (a retry's included), resume or Verify start,
after the count and before its live-session check, under the same
sessions.lock, forge reaps the finished sessions of that phase or Verify
that claude agents --json --all still lists as working or blocked: the
phase's sessions ("<project> P<N>[R<k>] <track>/<feature>", the legacy
"<project> <track>-<feature> Phase <N>[ retry <k>]", or the session its
last start event names) or the feature's verify session. A session is
finished when its record exists (the phase's result.json, or
STATE/features/<track>-<feature>/verify.json for Verify) or when its
transcript ends in assistant text holding a line starting "result:"
outside a ``` fence, read as above. Each finished one is removed with
claude rm <id> alone, never claude stop, which a restart can undo; then
claude agents --json --all is listed again every 0.5 s for up to 5 s,
and an id no longer listed, or no longer working or blocked, counts as
reaped, as does one whose claude rm failed and that is no longer listed.
An unfinished live session is never removed: the start is refused as
below.

A start it refuses or skips prints "forge: <kind> <target> not started:
<reason>" on stderr (kind phase, verify or ship; target the phase
number or <track>/<feature>) and goes on with the other due phases:
  - a phase or Verify that already has a live unfinished session, the
    reason naming the session; nothing is held
  - a finished session that claude rm cannot remove: a failed claude rm
    whose session is still listed, or one still working or blocked 5 s
    after claude rm, the reason naming the session, its id and that it
    is finished but still running after claude rm; nothing is held
  - a phase worktree with uncommitted changes that keep git from
    merging forge/<track>-<feature> into it: git's output is printed on
    stderr and the reason is "worktree <w> has uncommitted changes";
    nothing is held, and the next forge implement, done, next or resume
    that finds the worktree clean starts it
  - a claude --bg that fails to start: the reason is "claude --bg
    exited <s>: <last stderr line>", or "root <path> is not trusted by
    Claude Code" when claude's stderr starts "Workspace not trusted",
    <path> the main checkout of the session's cwd; it logs no start
    event, does not count the session, and records the phase or Verify
    in held.jsonl as a held start is, printing the same "forge: recorded
    the held <kind> <target>; forge watchdog starts it once room frees"
    line, so forge watchdog retries it
Each refused kind and target sends one notification per run through
forge's notify, titled "forge: launch refused" with body "<root
basename> <kind> <target>: <reason>"; a failed start already recorded
in held.jsonl sends none, so watchdog rescans do not repeat it, and a
failed notify only warns. After all its other work (the other starts
and holds) implement then exits 8, as do forge done, next and resume.
A capacity hold (sessions or memory) is no refusal: it
sends no notification and the exit stays 0.

Exit codes:
  0  started what was due; any capacity hold is recorded
  1  the feature is not ready or allocated, has a live session, a fresh
     run's branch already exists, a worktree cannot be created, or
     another failure
  8  a launch was refused or skipped, already reported

STATE below is the project root's state dir (see forge paths --help).

Reads:
  .forge/tracks/<track>.json
  STATE/features/<track>-<feature>/split.json
  STATE/phases/NN-slug/{spec,result}.json, events.jsonl
  .forge/repos.json
  claude agents --json, claude agents --json --all
  /proc/meminfo
  STATE/phases/*/events.jsonl, STATE/features/*/events.jsonl of every
    project or child repo with a live phase or verify session
                                  (their offsets)
  ~/.claude/projects/*/<sessionId>.jsonl, git status of their cwd
                                  (done quick, debug and discuss sessions)
  ~/.claude/projects/*/<sessionId>.jsonl
                                  (live sessions of a phase or Verify
                                   about to start)

Writes:
  the worktrees and branches above, when missing
  the Claude sessions it removes
  <git common dir>/forge-reaped.log   (one line per removed session)
  <git common dir>/info/exclude   (see forge exclude --help)
  STATE/phases/NN-slug/events.jsonl   (start event)
  ${XDG_RUNTIME_DIR:-~/.local/state}/forge/sessions.lock
  ${XDG_STATE_HOME:-~/.local/state}/forge/held.jsonl, held.jsonl.lock
                                (held starts)

Example:
  forge implement forge/run
