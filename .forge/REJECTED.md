# Rejected

## Rejected
- A standing decision log — most entries were never ratified; outcomes live in RULES/ARCHITECTURE/CONVENTIONS, rejections here.
- Nightly learning pipeline — cost without product value.
- Gates that enforce process instead of product correctness — they take code away from the product.
- Project data in a router file — it goes stale; the router is rendered.
- Shipping global instructions or editing any `CLAUDE.md` — those files are the user's; forge uses `.claude/rules/forge.md`, skills, agents and hooks.
- Setting `defaultMode` or the bypass skip key in user settings — forge's own sessions pass their permission mode at launch.
- Installing plugins by default — Codex and Impeccable are opt-in.
- Trash-staging prune rule — left orphaned files with no cleanup.
- Code comments — cost tokens and go stale.
- Dashboard-driven autonomous planner-worker factory — terminal sessions with in-project context proved more effective.
- Track review gates (a track `gate` tag that blocks closing it and opening other tracks) — they gate process, not product correctness.
